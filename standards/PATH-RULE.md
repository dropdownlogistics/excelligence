# Excelligence path rule

One rule for every surface that walks the graph: the explorer's Path Finder,
the `/paths/` step labels, the MCP server (`find_path`, `prerequisites`), and
what `llms.txt` tells AI collaborators.

## Edge direction

A learning path moves from what you learn first to what you learn next.

| Edge in `excelligence.json` | Meaning | Learning step |
|---|---|---|
| `A LEADS_TO B` | after A, go to B | A → B |
| `A DEPENDS_ON B` | A needs B, so B comes first | B → A (reversed) |
| `A PAIRS_WITH B` | learned together | A → B and B → A |

When more than one relation joins the same step, it is reported as the
strongest: LEADS_TO, then DEPENDS_ON, then PAIRS_WITH.

## Shortest path

Breadth-first search over those learning steps, starting from the start
entry. Neighbours are visited in ascending id order, so the same registry
always gives the same path.

## Prerequisites

`prerequisites(X)` is the transitive closure of X's DEPENDS_ON targets: every
entry X depends on, every entry those depend on, and so on. LEADS_TO and
PAIRS_WITH neighbours are context, not prerequisites.

## Curated paths

The twelve paths on `/paths/` are curated sequences. They are not generated by
this rule, and a step is not always joined to the one before it by an edge.
The page labels each step with the relation that joins it to the previous step
under this rule, or "curated step" when there is none.

## Implementations

- `lib/path-rule.js`: used by `/explorer/` and `/paths/`
- `mcp/excelligence_mcp.py`: `_learning_adjacency`, `_shortest_path`, `_prerequisites`

If you change this rule, change it here first, then change both
implementations. They have been checked to return identical shortest paths
for all 15,129 ordered entry pairs and identical prerequisite sets for all
123 entries.
